# AirportManager

A browser-based airline and airport management game. Build a route network,
manage aircraft and hubs, compete with rival airlines, and explore a world map
or an Earth globe with satellite terrain and night lights.

## Run locally

Requires Node.js 20.19+ on the Node 20 release line, or Node.js 22.12+.

```sh
npm ci
npm run dev
```

Open the local address printed by Vite. Game progress is stored in the browser.

## Build and test

```sh
npm test
npm run build
npm run preview
```

The production build is generated in `dist/`.

## Deploy to Vercel

Import this repository as a new Vercel project using the Vite framework preset,
`npm run build` as the build command, and `dist` as the output directory.
Add the desired subdomain under the project's Settings → Domains and follow
Vercel's displayed DNS instructions.

## Install on a phone and play offline

After deployment over HTTPS, open the game and choose **More → Install app**
(or **Install on your phone** on the start screen).

- **iPhone / iPad:** in Safari, choose Share → Add to Home Screen. Leave
  **Open as Web App** enabled if shown, then tap Add.
- **Android:** use the game's Install app button when Chrome offers it,
  or Chrome's menu → Install app / Add to Home screen.

Keep the game open online until the app screen says **Ready for offline play**.
The game and base maps can then reopen offline. Detailed satellite tiles load
as you explore online; a bounded cache retains recent tiles. Uncached regions
use the base imagery offline. Game progress remains in this device's browser
storage; there is no cloud sync or cross-device save transfer.

Updates download in the background. **More → Install app / App & updates**
shows **Save & update** when a new version is ready. Applying it saves progress
before reloading; an update does not interrupt an active game automatically.
Closing all app windows also allows a downloaded update to activate.

The service worker is generated by `npm run build` and enabled only in production
builds. Test it locally with `npm run build` followed by `npm run preview` on a
separate port from the development server. Vercel uses the same build command;
`vercel.json` keeps the service worker fresh. Development mode does not register
a worker. The build precaches only the app files and small base images, not the
complete satellite library. Service worker caches never contain game saves.

## Satellite imagery

Terrain uses NASA Blue Marble Next Generation, August 2004. Night lights use
NASA Black Marble 2016. These are satellite composites, not live imagery.

The images in `public/textures/` are required game assets. They include local
detail tiles that load only for the visible region as the player zooms in.
The imagery library is approximately 620 MiB; players do not download the
whole library at startup. Moving these assets to external storage requires
updating the image loader and deployment configuration first.

Source credits, processing details, and original download links:

- [Terrain](public/textures/terrain-source.txt)
- [Night lights](public/textures/night-lights-source.txt)

The scripts in `tools/` can regenerate the tiles with Python and Pillow from
the documented NASA source images. Original downloads are not part of this
repository. The generated tiles are included so a checkout can run and build
without downloading or processing the original datasets.
